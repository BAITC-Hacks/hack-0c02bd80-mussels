# AI Sana: Платформа геймификации практических бизнес-задач

Работающий MVP платформы для трансформации первоначальных потребностей бизнеса в качественные карточки задач, их объективного рейтингования и открытого выбора студенческих команд.

Разработано в рамках 5-часового практического хакатона AI Sana (трек: Education & Gamification).
Репозиторий проекта: [https://github.com/BAITC-Hacks/hack-0c02bd80-mussels](https://github.com/BAITC-Hacks/hack-0c02bd80-mussels)

---

## 1. Архитектура системы

Платформа построена по принципу модульного монолита на Python со специализированными слоями представления:

- **Автономное веб-приложение (`server.py`, `templates/`, `run_web.sh`)**: Основной веб-интерфейс на базе FastAPI, Jinja2, Tailwind CSS и Alpine.js на порту 8000. Реализован в чистой белой эстетике (Clean Tech White) с круговыми SVG-спидометрами готовности, реактивной шкалой контрольных этапов и нулевым оверхедом сборки.
- **Резервная панель (`app.py`, `run.sh`)**: Демонстрационная панель на базе Streamlit на порту 8501.
- **Двухрежимный AI-движок (`services/ai_generator.py`)**: 
  - Основной режим: OpenAI (`gpt-4o-mini`) для контекстного анализа пробелов в ТЗ и синтеза карточки.
  - Резервный режим: Локальный детерминированный генератор (Local Fallback), обеспечивающий 100% стабильность демонстрации даже при отсутствии сети или API-ключа.
- **Движок скоринга (`services/scoring.py`)**: Прозрачная аддитивная формула расчета рейтинга (0–100 баллов) с генерацией подсказок по улучшению.
- **Многомерный алгоритм рекомендаций (`services/recommendation.py`)**: Персонализированный подбор задач для команд по доменным интересам (40%), профилю инженерных компетенций (40%) и уровню готовности ТЗ (20%).
- **Файловое хранилище (`services/storage.py`)**: JSON-хранилище в директории `data/` с атомарной записью, поддержкой сидинга и кнопкой мгновенного сброса.
- **Синтетический датасет (`services/seed_data.py`)**: 5 черновиков, 5 полных карточек задач, 5 профилей команд, 5 предложений и контрольные этапы (milestones).
- **Модуль UI-компонентов (`services/ui_components.py`)**: Генерация векторных дуговых спидометров рейтинга на чистом SVG без сторонних библиотек.

## 2. Формула рейтинга готовности задачи

Рейтинг отражает готовность конкретной бизнес-задачи к студенческой разработке и рассчитывается строго аддитивно по подтвержденным полям:

| Показатель | Макс. балл | Как начисляются баллы |
| :--- | :---: | :--- |
| **Контекст и потребность** | 20 | Понятно текущее положение дел и требуемые изменения |
| **Данные и материалы** | 20 | Указаны доступные датасеты, примеры диалогов, ссылки |
| **Ожидаемый результат** | 15 | Описан конкретный артефакт (бот, сервис, модель, дашборд) |
| **Критерии успеха** | 15 | Сформулированы измеримые метрики приемки решения |
| **Ограничения** | 10 | Зафиксированы сроки, стек технологий, безопасность |
| **Пользователи** | 10 | Определена целевая аудитория будущего решения |
| **Связь с бизнесом** | 10 | Указаны прямые контакты, формат синков и консультаций |
| **ИТОГО** | **100** | Полная шкала готовности |

### Уровни готовности:
- **0–39 баллов — Черновик**: задача видна в каталоге, но снабжена отметкой о необходимости доработки.
- **40–69 баллов — Рабочая**: студенты могут подавать отклики, задача включается в рекомендации.
- **70–89 баллов — Готовая**: задача занимает повышенную позицию в общем каталоге.
- **90–100 баллов — Приоритетная**: задача полностью готова к работе и выделяется визуальным бейджем.

## 3. Правила каталога и рекомендации студентам

1. **Открытость пула**: Все подтвержденные задачи доступны всем студенческим командам без скрытия.
2. **Сортировка по готовности**: Чем выше рейтинг задачи, тем выше ее позиция в каталоге.
3. **Многомерные рекомендации**:
   - Система сопоставляет профиль команды и задачу без жесткой фиксации на языке программирования:
     - Совпадение домена бизнеса (Retail, FinTech, EdTech и др.): 40%
     - Совпадение инженерного направления (NLP, Data Science, Fullstack и др.): 40%
     - Готовность задачи к разработке: 20%
   - Карточки получают бейдж соответствия с текстовым объяснением AI, но не блокируют выбор любых других задач.
4. **Принцип исключительно ручного выбора**:
   - Автоматическое назначение команд платформой или искусственным интеллектом категорически запрещено.
   - Представитель бизнеса лично просматривает список предложений и вручную нажимает "Выбрать команду" или "Отклонить".

## 4. Геймификация фактического прогресса (Шаг 8)

После выбора команды представитель бизнеса ведет контрольные этапы проекта:
- Приемка этапа разработки (прототип, интеграция, финал).
- При нажатии "Подтвердить этап" студенческой команде начисляются баллы прогресса (XP).
- Текущий уровень XP команды отображается в профиле и влияет на привлекательность команды для будущих задач.

## 5. Быстрый запуск

### Требования:
- Python 3.9+
- Установленные зависимости

### Установка:
```bash
# Клонирование репозитория
git clone https://github.com/BAITC-Hacks/hack-0c02bd80-mussels.git
cd hack-0c02bd80-mussels

# Создание и активация виртуального окружения
python3 -m venv venv
source venv/bin/activate

# Установка зависимостей
pip install -r requirements.txt
```

### Запуск основного веб-приложения (FastAPI + Tailwind CSS, порт 8000):
```bash
./run_web.sh
# или напрямую:
uvicorn server:app --host 0.0.0.0 --port 8000 --reload
```
Основное приложение откроется в браузере по адресу: **`http://localhost:8000`**.

Доступные разделы веб-приложения:
- **`http://localhost:8000/`** (или `/constructor`) — Конструктор задачи с AI-диалогом, быстрым черновиком и круговым спидометром готовности (0–100).
- **`http://localhost:8000/catalog`** — Общий каталог подтвержденных задач с живой фильтрацией по отраслям, статусам готовности и открытым доступом.
- **`http://localhost:8000/student`** — Кабинет студенческой команды с балансом XP, реестром выполненных этапов и многомерным AI-мэтчингом (40% домен, 40% стек, 20% готовность).
- **`http://localhost:8000/business`** — Кабинет бизнеса со списком откликов, ручным выбором исполнителя (ADR-0003), интерактивной шкалой контрольных этапов и подтверждением (+XP).
- **`http://localhost:8000/jury-demo`** (редирект с `/demo`) — Экспресс-демонстрация для жюри: интерактивный гид по всем 5 шагам сценария за 3 минуты, памятка архитектурных решений и кнопка сброса данных к эталону.

### Запуск резервной панели (Streamlit, порт 8501):
```bash
./run.sh
# или напрямую:
streamlit run app.py --server.port 8501
```
Резервная панель откроется по адресу: **`http://localhost:8501`**.

### Запуск автоматических тестов:
```bash
pytest tests/
```

## 6. Сценарий 3-минутной демонстрации для жюри

На защите или при независимой проверке эксперты могут открыть раздел **`/jury-demo`** (или `http://localhost:8000/demo`) и пройти сквозной сценарий:

1. **Ввод слабого черновика (Шаг 1)**:
   - В разделе Конструктора нажать **"Заполнить эталонный черновик"**.
   - Появляется сырая формулировка задачи ритейла со стартовым рейтингом ~20–30 баллов ("Черновик").
2. **Пошаговое AI-интервью (Шаг 2)**:
   - AI-агент выявляет недостающие блоки ТЗ и задает целевые вопросы (о данных, результатах, критериях, ограничениях).
   - Используются кнопки **"Быстрый ответ для жюри"** для мгновенного прохождения интервью.
3. **Синтез ТЗ и рост рейтинга на спидометре (Шаг 3)**:
   - На спидометре отображается рост рейтинга с **20 до 95 баллов** (статус: **Приоритетная**).
   - Генерируются 3 контрольных этапа разработки (milestones) с весами 25 + 35 + 40 = 100 XP.
   - Задача подтверждается и публикуется в открытый каталог.
4. **Каталог и персональные AI-рекомендации студентам (Шаг 4)**:
   - В каталоге опубликованная задача занимает верхнюю позицию благодаря высокому рейтингу готовности.
   - В кабинете студента команда **NeuralMinds** получает рекомендацию с высоким соответствием (40% домен, 40% стек, 20% готовность) и текстовым AI-обоснованием.
5. **Ручной выбор бизнеса и начисление баллов прогресса (Шаг 5)**:
   - В кабинете бизнеса представитель вручную принимает решение (принцип **ADR-0003: категорический запрет автоназначения**).
   - При нажатии **"Подтвердить этап (+XP)"** студентам начисляются баллы прогресса, шкала этапов и профиль команды обновляются мгновенно.
